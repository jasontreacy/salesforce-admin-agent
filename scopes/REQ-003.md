## PLAIN ENGLISH

**What they're asking for.** Dana wants three unrelated things bundled as a clean-up: remove the
Order Channel field, let every rep edit every opportunity, and rename two sales stages.

**What's actually going on.** Each of the three is outside what this agent is allowed to do, for
a different reason, and bundling them hides that.

1. *Delete Order Channel.* The pipeline never deletes metadata (`config/metadata-allowlist.json`,
   `destructiveChanges`). The field is on the tracked Opportunity layout and has read/edit access
   in the `Lakeside_Wholesale_Rep` permission set, so it is not unused in the metadata sense even
   if nobody fills it in. A human runs deletions, after checking reports and the layout.
2. *Modify All on Opportunity.* That is an org-wide access decision. It lives on a profile or as an
   object permission on a permission set, and it means every rep can edit and delete every deal.
   `Profile` is a denied type, and granting Modify All through the permission set would be a
   policy change dressed up as a config task. This needs a conversation with Dana about what
   problem she is solving; "fix each other's deals" usually wants a sharing rule or a team, not
   Modify All.
3. *Rename stages.* Opportunity stages are a `StandardValueSet`, a denied type, because every
   report, dashboard and the one existing validation rule depend on the stage labels and the
   closed/won flags. Renaming is possible but is a change-managed task, not an agent task.

**What it takes.** A call with Dana to split this into three decisions. Items 1 and 3 can then be
done by a human admin with a change record. Item 2 should probably become a different request.

**What I'm not sure about.** Whether Dana knows Modify All includes delete. Ask.

## CONCEPT
Dana wants Order Channel deleted, Modify All on Opportunity for all reps, and two stages renamed.

## TASKS
Not scopable by this agent. Three separate human decisions:
1. Deletion of `Opportunity.Order_Channel__c`: human-run, after removing it from `Opportunity Layout` and `Lakeside_Wholesale_Rep`, and checking reports that filter on it.
2. Modify All: clarify the underlying problem with Dana; likely a sharing rule or opportunity team instead.
3. Stage renames (`Perception Analysis` → `Sample Sent`, `Id. Decision Makers` → `Buyer Meeting`): human-run `StandardValueSet` change with a check of reports and `Rush_Order_Close_Within_14_Days`.

## CONSIDERATIONS
1. Nothing in this request can proceed through the agent pipeline. `metadata_types` is intentionally empty so `guard-scope.sh` refuses it even if someone flips the status.

## OUTCOMES
1. Dana has a reply explaining the split and the Modify All question.
